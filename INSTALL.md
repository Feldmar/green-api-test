Установка
1. Клонирование репозитория
git clone https://github.com/Feldmar/green-api-test.git

2. Установка зависимостей
npm install

3. Настройка окружения
Создайте файл .env в корне проекта:
и вставьте туда переменную "apiUrl" из вашего инстанса MAX в GREEN_API

Пример:
VITE_GREEN_API_URL=https://api.green-api.com 

4. Запуск в режиме разработки
npm run dev
Приложение откроется на http://localhost:5173.

Использование
Подключение к GreenAPI
Зайдите в личный кабинет green-api.com.

Создайте инстанс и скопируйте:

idInstance

apiTokenInstance

Откройте приложение и введите эти данные в форму подключения.

Отсканируйте QR-код в кабинете GreenAPI, чтобы авторизовать инстанс.

Создание чата
Введите номер телефона собеседника в формате + и без пробелов: например +79991234567.

Нажмите «Создать чат».

Приложение вызовет checkAccount и, если аккаунт существует, откроет диалог.

Отправка сообщений
Введите текст в поле ввода внизу чата.

Нажмите Enter или кнопку отправки.

Сообщение появится сразу со статусом sending, затем сменится на sent и далее по мере обновлений от GreenAPI.

Приём сообщений
Входящие сообщения появляются автоматически - приложение опрашивает receiveNotification каждые 2 секунды. В UI попадают только сообщения из текущего открытого чата.

Как работает фильтрация
GreenAPI в режиме long-polling возвращает все уведомления инстанса: личные чаты, группы, каналы, боты. Отфильтровать их на уровне сети нельзя - фильтрация происходит в App.tsx после receiveNotification.

Логика:

outgoingMessageStatus - обновляет статус сообщения, если idMessage есть в текущем списке и chatId совпадает.

incomingMessageReceived / outgoingMessageReceived - добавляет сообщение в UI, только если:

senderData.chatType === 'user' (приватный чат);

senderData.chatId совпадает с chatRef.current.chatId.

deleteNotification вызывается для всех уведомлений - это сдвиг курсора очереди, а не подтверждение «своего» сообщения. Если удалять только свои, поллинг встанет.

⚠️ В DevTools => Network вы будете видеть все уведомления инстанса. Это ожидаемое поведение GreenAPI. В UI попадают только отфильтрованные.

Частые проблемы
«На этом номере не найден аккаунт MAX»
Номер не зарегистрирован в MAX или введён в неверном формате. Убедитесь, что номер вводится c +, без пробелов и дефисов.

Сообщения не приходят
Проверьте, что инстанс авторизован в кабинете GreenAPI (QR-код отсканирован).

Убедитесь, что chatId открытого чата совпадает с chatId в вебхуках. Формат может отличаться (212474742 vs 212474742@c.us) — нормализация в normalizeChatId срезает всё после @.

Проверьте консоль: временные console.log в App.tsx показывают chatId, chatType и результат сравнения.

Очередь уведомлений переполнена
Если не вызывать deleteNotification, очередь на стороне GreenAPI забьётся. Убедитесь, что вызов не обёрнут в условия и происходит для всех уведомлений.

«Подключение…» не меняется на «Подключено»
Индикатор загорается после первого успешного receiveNotification. Если он не загорается - проверьте токены и доступность api.green-api.com.

Ограничения
Поддерживаются только текстовые сообщения.
Фильтрация происходит только по текущему открытому чату - история предыдущих чатов не сохраняется.
Long-polling каждые 2 секунды - не WebSocket, задержка приёма до 2 секунд
В Network видны все уведомления инстанса (ограничение GreenAPI).
